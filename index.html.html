ازاي الفرونت إند بيكلّم الباك إند

المثال: صفحة تسجيل حساب جديد. الفرونت يبعت البيانات، والباك يحفظها في قاعدة البيانات ويرد.

  • الفرونت إند
  • الباك إند
  • قاعدة البيانات

الربط كله: أربع حاجات لازم تتطابق

الفرونت والباك برنامجين منفصلين. بيتكلموا بس عن طريق طلب HTTP وردّ JSON. لو الأربع حاجات دي متطابقة في الطرفين، الربط يشتغل.

العنوان (URL)

الفرونتfetch(`${API}/api/auth/register`)
الباكapp.use("/api/auth", routes)
router.post("/register", register)

البريفكس /api/auth + المسار /register = نفس العنوان اللي في الفرونت.

نوع الطلب (Method)

الفرونتmethod: "POST"
الباكrouter.post(...)

أسماء الحقول في JSON

الفرونت{ name, email, password }
الباكconst { name, email, password } = req.body

شكل الرد

الباكres.status(201).json({ token })
الفرونتconst result = await res.json()
result.token

الداتا بتتحول إزاي في الطريق

نفس المعلومة بتغيّر شكلها أربع مرات من الـinput لحد الـDB.

في الفورمنصوص مكتوبة: Ali / ali@mail.com / 123456
↓ .value يقرأ كل حقل
في الجافاسكريبت: كائن{ name: "Ali", email: "ali@mail.com", password: "123456" }
↓ JSON.stringify(data) يحوّله لنص
على الشبكة: نص JSON'{"name":"Ali","email":"ali@mail.com","password":"123456"}'
↓ express.json() يرجّعه كائن
في الباك: req.body{ name: "Ali", email: "ali@mail.com", password: "123456" }
↓ كود المصادقة يشفّر الباسورد ثم User.create()
في قاعدة البيانات: سجل جديد{ _id: "…", name: "Ali", email: "ali@mail.com", password: "$2b$10Xk…" }

رحلة الطلب من أولها لآخرها

  1. المستخدم يكتب بياناته ويضغط زرار التسجيل.
  2. الجافاسكريبت يجمع القيم ويبعتها بـ fetch كطلب POST.
  3. السيرفر يوجّه الطلب للـRoute، والـController يقرأ req.body.
  4. كود المصادقة بتاعك يتحقق ويشفّر الباسورد.
  5. الباك يدخل المستخدم في الـDB بـ User.create.
  6. الـDB تأكد الحفظ وترجع الـid.
  7. الباك يرد بـ JSON فيه التوكن، أو رسالة خطأ.
  8. الفرونت يقرأ الرد، يحفظ التوكن ويحوّل المستخدم.

الكود خطوة خطوة

كل خطوة تحت فيها الكود، وبعده شرح كل سطر مهم بيعمل إيه. اللون بيقولك الكود ده في أنهي طرف.

الخطوة 1: الفورم في الصفحة

register.html
<form id="registerForm">
  <input id="name" type="text" placeholder="Name" required>
  <input id="email" type="email" placeholder="Email" required>
  <input id="password" type="password" placeholder="Password" required>
  <button type="submit">Register</button>
  <p id="msg"></p>
</form>

<script src="register.js"></script>
  • <form id="registerForm">الفورم لازم له id عشان الجافاسكريبت يمسكه.
  • <input id="email" ...>كل حقل له id. من خلاله الجافاسكريبت هيقرأ القيمة. required يمنع الإرسال لو الحقل فاضي.
  • <button type="submit">لما يتضغط، الفورم بيعمل حدث اسمه submit. ده اللي هنمسكه في الخطوة الجاية.
  • <p id="msg">مكان فاضي هنكتب فيه رسالة الخطأ لو حصلت.
  • <script src="register.js">يحمّل ملف الجافاسكريبت. لازم يكون بعد الفورم عشان العناصر تبقى موجودة.

  • awaitيوقف الدالة لحد ما الرد يرجع من السيرفر، وبعدين يكمّل.

الخطوة 4: نقرأ الرد ونتصرف

register.js (كمّل)
    const result = await res.json();

    if (!res.ok) {
      msg.textContent = result.message;
      return;
    }

    localStorage.setItem("token", result.token);
    window.location.href = "/dashboard.html";
  } catch (err) {
    msg.textContent = "Server is not reachable";
  }
});
  • await res.json()يقرأ جسم الرد ويحوّله لكائن جافاسكريبت.
  • if (!res.ok)res.ok بتبقى true لو الحالة بين 200 و299. لو الباك رد 400 (إيميل مكرر مثلاً)، fetch مش بيرمي خطأ. لازم نفحص بنفسنا.
  • msg.textContent = result.messageنعرض رسالة الباك للمستخدم، وreturn يوقف باقي الدالة.
  • localStorage.setItem("token", ...)نحفظ التوكن في المتصفح. هنحتاجه في أي طلب لصفحة محمية. (في مشاريع كبيرة بيُستخدم cookie من نوع httpOnly لأنه أأمن.)
  • window.location.href = ...ينقل المستخدم لصفحة تانية بعد النجاح.
  • catch (err)بيشتغل لو الطلب نفسه فشل: السيرفر واقف أو البورت غلط.

الخطوة 5: السيرفر نفسه

server.js
const express = require("express");
const cors = require("cors");
const mongoose = require("mongoose");

const app = express();

app.use(cors());
app.use(express.json());

app.use("/api/auth", require("./routes/auth"));

mongoose.connect(process.env.MONGO_URI)
  .then(() => app.listen(5000));
  • app.use(cors())الفرونت (مثلاً على بورت 5173) والباك (على 5000) أصلين مختلفين. المتصفح يحجب الرد إلا لو الباك سمح. من غيره بتشوف خطأ CORS.
  • app.use(express.json())ميدل وير بيقرأ جسم الطلب JSON ويحطه في req.body. من غيره req.body بيبقى undefined.
  • app.use("/api/auth", require("./routes/auth"))أي طلب عنوانه يبدأ بـ /api/auth يروح لملف الـroutes.
  • mongoose.connect(...)يفتح الاتصال بقاعدة البيانات.
  • .then(() => app.listen(5000))بعد ما الاتصال ينجح، السيرفر يبدأ يستقبل طلبات على بورت 5000.

الخطوة 6: الـRoute هو نقطة اللقاء

routes/auth.js
const router = require("express").Router();
const { register, login } =
  require("../controllers/authController");

router.post("/register", register);
router.post("/login", login);

module.exports = router;
  • router.post("/register", register)يقول: لو جه طلب POST على /register، شغّل الدالة register. مع البريفكس من server.js يبقى العنوان الكامل /api/auth/register. ده نفس اللي كتبته في fetch.
  • module.exports = routerنصدّر الـrouter عشان server.js يستخدمه.

  • const { name, email, password } = req.bodyreq.body هو الكائن اللي بعته الفرونت. السطر ده بيطلّع 3 قيم منه بنفس أسماء المفاتيح.
  • // your auth codeده الجزء اللي انت عارفه وسيبناه: التحقق والتشفير وإنشاء التوكن. المهم تعرف هو بيدّي إيه: hashedPassword وtoken.
  • await User.create({ ... })ده السطر اللي بيدخل الداتا في قاعدة البيانات. هنشرحه في الخطوة الجاية.
  • res.status(201).json({ ... })يرد على الفرونت. 201 = اتعمل بنجاح. الكائن ده هو اللي الفرونت هيقراه بـ res.json(). يعني token هنا = result.token هناك.
للأخطاء: ارجع res.status(400).json({ message: "Email already used" }). الفرونت هيلاقي res.ok بـ false ويعرض result.message.

الخطوة 8: الموديل ودخول الداتا للـDB

models/User.js
const mongoose = require("mongoose");

const userSchema = new mongoose.Schema({
  name: String,
  email: { type: String, unique: true },
  password: String,
});

module.exports = mongoose.model("User", userSchema);
  • new mongoose.Schema({ ... })يوصف شكل السجل: إيه الحقول ونوع كل واحد.
  • unique: trueقاعدة البيانات نفسها ترفض إيميل مكرر.
  • mongoose.model("User", userSchema)يصنع الكلاس User اللي استخدمناه. بيتخزن في collection اسمها users.
  • User.create({ ... })يتحول لأمر insertOne على الـDB، وبيضيف السجل الجديد ويرجّع السجل ومعاه _id.
لو بتستخدم SQL (MySQL أو Postgres)، الفكرة نفسها والأمر هو: INSERT INTO users (name, email, password) VALUES (?, ?, ?). بتبعت القيم الثلاث اللي طلعت من req.body.

تسجيل الدخول: نفس الفكرة بتغييرين

صفحة الـlogin بنفس الخطوات. اللي بيتغير العنوان والبيانات المبعوتة، وبعدها التوكن بيسافر مع كل طلب لصفحة محمية.

الفرونت: طلب الدخول

login.js
const res = await fetch(`${API}/api/auth/login`, {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ email, password }),
});
  • /api/auth/loginعنوان تاني، يطابق router.post("/login", login).
  • { email, password }بس حقلين. مفيش name. والباقي زي التسجيل: نقرأ الرد، نحفظ التوكن، ونحوّل.

بعد الدخول: طلب لصفحة محمية

profile.js
const token = localStorage.getItem("token");

const res = await fetch(`${API}/api/profile`, {
  headers: { Authorization: `Bearer ${token}` },
});
const profile = await res.json();
  • localStorage.getItem("token")نجيب التوكن اللي حفظناه وقت الدخول.
  • Authorization: `Bearer ${token}`نبعت التوكن في الهيدر. الميدل وير بتاعك في الباك يقرأ الهيدر ده ويتحقق منه، وبعدين يسمح للطلب يكمّل.

لما الربط ما يشتغلش

افتح أدوات المطوّر في المتصفح (F12)، وروح تبويب Network، وبعدين اضغط زرار التسجيل. اضغط على الطلب هتلاقي Payload (اللي الفرونت بعته) وResponse (اللي الباك رد بيه). كده تعرف المشكلة في أنهي طرف.

  • الصفحة بتعمل refresh ومفيش طلبنسيت e.preventDefault().
  • خطأ CORS في الـConsoleالباك محتاج app.use(cors())، أو العنوان بتاع الباك غلط.
  • req.body فاضي أو undefinedنسيت app.use(express.json())، أو الفرونت ما بعتش Content-Type: application/json.
  • 404 Not Foundالمسار أو الـmethod غلط. راجع البريفكس /api/auth وrouter.post.
  • الطلب نجح بس الاسم اتحفظ فاضياسم المفتاح مختلف. الفرونت بعت username والباك بيقرأ name.
  • Failed to fetchالسيرفر مش شغال، أو البورت مختلف عن اللي في API.
